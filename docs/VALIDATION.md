# 별도 PC 검증 및 릴리스 기록

개발 PC에서 PowerSI, 사용자 제공 BAT/Tcl, 실제 SPD 시뮬레이션은 실행하지 않습니다. 안전 모드·자동 테스트·설치 시험만 사용합니다. 실제 연동은 PowerSI 실행이 허용된 별도 Windows PC에서만 검증합니다. 설치·업데이트 관리를 위한 정식 Release 게시와 PowerSI 연동 실측 통과는 별개로 기록합니다.

## 검증 준비

1. 깨끗하게 커밋한 소스로 `tools/Build.ps1`을 실행합니다. 설치 EXE, SHA-256 파일, `build-manifest.json`을 함께 보관합니다.
2. 별도 PC에서 설치파일 SHA-256을 확인하고 PowerSI 2025.1의 정확한 버전 및 Windows 버전을 기록합니다. 검증용 SPD는 공개 가능하거나 별도 허가된 복사본만 사용합니다.
3. 각 **지원하려는 저장 모드**를 별도 사례로 준비합니다. SPD의 기존 모드와 설정이 유지되는지 확인합니다. 검증하지 않은 모드를 지원한다고 표기하지 않습니다.

## 필수 사례

| 사례 | 통과 조건 |
|---|---|
| GUI 시작 | `-b` 없이 새 PowerSI 창이 표시되고 생성된 `-tcl` 스크립트가 실행됨 |
| 실행 경로 | 빈 경로에서 시작하면 탐색 결과가 실제 설정에 저장됨; 설치 없음·잘못된 명시 경로는 시작 전에 안내; 예약 대기 중 실행 파일이 사라져도 작업·예약을 대기로 보존 |
| 실패 상세 | 실패 상태 더블클릭 또는 우클릭 작업 상세로 오류를 복사; 실행 폴더 생성 전 실패는 전체 스케줄러 로그 폴더로 연결; 후속 확인에서 실패 건수를 유지 |
| 정상 시뮬레이션 | 파일 열기, 실제 시작, 모드에 맞는 완료, 저장, 자체 PowerSI·solver 종료를 각각 확인 |
| 완료 판정 | 명령 반환이나 이전 완료 출력만으로 저장하지 않음; START→DONE→START는 다시 완료할 때까지 보류 |
| 기존 PowerSI | 실행 중·일시정지·라이선스 대기·유휴 상태에서 기대대로 대기/진행; 외부 PowerSI 저장·종료 없음 |
| 완료 후 지연 | 여러 창의 상태 읽기 시간이 관측 중단으로 오인되지 않음; 마지막/다음 확인 시각 갱신; 기본 60초 저부하 구간 이후 재검사로 무한 대기하지 않음 |
| 상태 표시줄 | 감시 상세의 실제 텍스트와 Busy/완료 상태가 일치; 동일 GUI의 연속 완료는 해당 GUI I/O만 제외하고 CPU·메모리는 계속 검사 |
| 외부 BbsCon 병행 | 허용 설정에서 확인된 BbsCon·콘솔 호스트의 부하를 제외하며 관측 합계와 판정 수치를 구분; 설정 해제 시 다시 차단; 다른 solver는 계속 검사 |
| 자체 BbsCon 정리 | 스케줄러가 직접 실행한 작업은 BbsCon 병행 설정과 관계없이 저장·자식 프로세스 정리가 끝나야 다음 작업 진행 |
| I/O 구분 | 기타 I/O는 진단에만 표시하고 읽기/쓰기 기준을 적용; 카운터 역행·PID 재사용·불완전한 관측은 계속 보류 |
| 순차/예약 | 일반 FIFO, 지난 예약 우선, 같은 예약 등록순, 미래 예약이 일반 작업을 막지 않음, 실행 중인 작업 비중단 |
| 시작 실패 | 열기/시작 거부를 기록하고 자체 실행만 정리; 확인된 종료 후 다음 작업으로 이동 |
| 불명확한 시작 | 활동이 있거나 관측 불가이면 제한시간 후 확인 필요; 강제 종료 없음 |
| 저장/정리 실패 | 오류와 실행 로그가 남고 다음 작업은 보류 |
| 종료·재시작 | 앱만 종료해도 PowerSI 유지; 다시 열면 완료 확인·저장·정리 연결; 신규 시작은 일시정지 |
| 자체 프로세스 조회 복구 | 종료된 자식 PID의 재사용과 조회 중 종료를 구분; 일시 조회 실패 후 현재 실행을 재확인하고 저장·종료 후 다음 작업 진행; 실제 접근 거부는 계속 대기 |
| 소유권 | PID 재사용·다른 PowerSI·살아 있는 solver·읽기 권한 오류에서 다른 프로세스를 제어하지 않음 |
| 경로·UI | 한글·공백·괄호·대괄호·달러 기호 경로, 다중 드롭 순서, 긴 파일명 왕복/끝 정지, 숨김 시 애니메이션 중지 |
| 트레이 | 더블클릭 복원, X 숨김, 두 번째 실행이 기존 창 복원, 트레이 종료 |
| 예약 복귀 | 절전 후 지난 예약 재평가, CPU/I/O 유휴 측정 재시작 |
| 설치 | 사용자 단위 설치·같은 AppId 업데이트·제거, 로그인 자동 시작 선택, 제거 후 큐 보존 |

새 모드의 로그 규칙은 실제 해당 실행에서 관측한 시작·완료 문구로 만듭니다. SPD 식별 패턴은 한 줄에 적용합니다. 경로·제품명·설계 내용이 들어간 로그나 화면은 공개 저장소에 올리지 마세요. 검증 기록은 비공개로 보관하고 공개 보고에는 비식별 결과만 적습니다.

## 증거와 게시

`validation-evidence.example.json`을 **저장소 밖**으로 복사합니다. `sourceCommit`, `installerSha256`은 실제 manifest에서 채우고, 수행한 필수 사례에 대해서만 `true`를 기록합니다. `workflows`에는 검증한 모든 모드와 GUI·시작·완료·저장·종료 결과를 각각 남깁니다. 빈 값을 추정하거나 미검증 사례를 통과로 바꾸지 않습니다.

```powershell
./tools/Publish-Release.ps1 `
  -InstallerPath ./artifacts/installer/SPD-Scheduler-Setup-0.1.6.exe `
  -EvidencePath C:/Validation/SPD-Scheduler-evidence.json `
  -ValidateOnly
```

같은 명령에서 `-ValidateOnly`를 제외하면 `v0.1.6` 정식 Release에 설치파일과 SHA-256을 게시합니다. 스크립트는 깨끗한 현재 HEAD, 빌드 manifest, 커밋·해시 일치를 검사합니다. `-EvidencePath`를 제공하면 증거와 설치파일의 일치 및 필수 통과 결과도 검사합니다. 실제 검증 후 소스나 설치파일을 바꾸면 다시 빌드·검증해야 합니다. 이 검사는 사람의 실측을 대체하지 않습니다.

사용자 요청에 따라 실측 전에도 설치·업데이트용 정식 Release를 게시할 수 있습니다. 이 경우 `-EvidencePath`를 생략하며, 릴리스 설명에 PowerSI 연동 검증이 아직 남아 있다고 자동 표시합니다. 미검증 증거를 통과로 변경하지 않습니다. 변경 설명은 `-NotesPath docs/releases/v0.1.6.md`로 지정할 수 있습니다.

## 현 개발 환경에서의 검증 범위

콘솔 회귀 테스트는 가짜 시간·어댑터·프로세스 스냅샷과 합성 로그로 수행합니다. PowerSI 자체, 생성된 Tcl, GUI `-tcl` 동작, 모드별 결과 저장은 테스트하지 않습니다.

안전 모드에서 합성 큐의 한글 긴 파일명과 두 행을 접근성 트리로 확인했습니다. Esc로 창이 숨겨지고 프로세스가 유지되며, 두 번째 실행은 종료 코드 0으로 끝나고 기존 창을 복원했습니다(기존 프로세스 하나만 유지). 파일 선택창도 열렸습니다. 현재 Computer Use 화면 캡처는 시간 초과하여 실제 다중 드롭, 스크롤 애니메이션, X 닫기, 트레이 더블클릭 등 시각 동작 확인은 남아 있습니다.
