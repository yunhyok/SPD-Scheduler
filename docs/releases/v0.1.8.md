SPD Scheduler v0.1.8

## 전처리 시작 인식과 자동 진행 복구

PowerSI가 실제 전처리를 수행하는데도 시작 신호를 인식하지 못해 `확인 필요`로 남던 경로를 수정했습니다.

- 현재 실행 전용 `output.log`의 알려진 전처리 기록을 시작 증거로 사용합니다. 같은 실행의 열기·시작 요청 이벤트와 실행 생성 시각 이후의 로그가 필요합니다. 별도 모드 규칙 없이도 `실행 중`으로 표시합니다.
- 시작 확인 제한시간을 넘겨도 해당 작업을 계속 관측합니다. 이후 시작이 확인되면 복구하며, 정상 완료·저장·자체 프로세스 정리 후 다음 작업으로 이어집니다. 사용자의 일시 중지, 수동 정리, 다른 오류로 인한 중지와 앱 재시작은 자동 해제하지 않습니다.
- 전처리와 명령 반환은 완료로 처리하지 않습니다. GUI 완료는 현재 실행의 시작 증거와 읽을 수 있는 미완료 상태 이후의 `Simulation Done.` 전이가 필요합니다. 상태가 읽히지 않거나 처음부터 Done인 경우에는 자동 저장하지 않습니다. 기존 작업별 완료 로그 규칙도 유지합니다.
- 자체 실행 중 **감시 상세**에 현재 실행 ID·PID·측정 시각·관측 결과·상태 문구를 제공합니다. 이전 외부 유휴 관측 수치를 현재 작업의 상태로 표시하지 않습니다.
- 확인 간격은 기존 분 단위 설정을 유지합니다. 실제 PowerSI의 설정이나 원본 SPD를 변경하지 않습니다.

## 업데이트 후 진행 중인 작업 연결

1. PowerSI는 그대로 두고 스케줄러만 트레이 메뉴의 **종료**로 닫습니다.
2. `SPD-Scheduler-Setup-0.1.8.exe`를 설치하고 스케줄러를 엽니다.
3. **지금 확인**을 누릅니다. 현재 실행에 전처리 기록이 있으면 기존 행이 `실행 중`으로 복구됩니다.
4. 앱 재시작 후 후속 큐는 일시정지 상태이므로 **시작**을 누릅니다. 진행 중인 파일을 다시 등록하거나 수동 완료할 필요는 없습니다.

이미 계산이 끝났고 시작 후의 미완료 GUI 상태를 한 번도 관측하지 못했다면 `확인 필요`로 표시하며 자동 저장·완료를 보류합니다. 이 경우 PowerSI에서 결과 저장을 직접 확인한 뒤 **수동 완료 처리… → 시작**을 사용합니다.

## 검증 범위

회귀 테스트 **176개 통과**. 가짜 프로세스·시간·로그로 늦은 전처리 시작, 시작 확인 보류의 복구, 순차 실행, 일시 중지·재시작 보존, 오래된 완료 문구와 다른 실행 로그 거부, 저장 직전 상태 재확인을 검증했습니다. 실제 고객 로그나 SPD는 배포물에 포함하지 않습니다.

이 PC에서는 실제 PowerSI, 사용자 BAT/Tcl, 실제 SPD를 실행하지 않았습니다. PowerSI의 GUI 상태 읽기 및 실제 완료·저장·종료의 연속 동작은 별도 허용 PC에서 확인해야 합니다.
