SPD Scheduler v0.1.2

## 변경 사항

- Windows가 재사용한 부모 PID 때문에 PowerSI보다 오래된 무관한 프로세스를 자식으로 합산할 수 있던 오류를 수정했습니다. 부모·자식의 생성 시각과 실제 프로세스 ID를 검증합니다. 실제 solver 자식은 부모가 종료되어도 계속 감시합니다.
- 하단 CPU를 전체 PC의 논리 프로세서 기준으로 표시합니다. 이전의 단일 코어 합계 100%는 논리 프로세서 64개에서 전체 CPU 약 1.56%에 해당합니다.
- **감시 상세**에서 PID·실행 파일명별 CPU, I/O, 메모리 변화와 초과한 기준을 확인하고 복사할 수 있습니다. 측정 시각과 평균을 계산한 구간도 표시합니다.
- 설정의 CPU 단위를 **CPU 한도 (1코어 %)**로 명확히 표시했습니다. 기존 값과 의미는 유지합니다. 단일 스레드 계산을 유휴로 잘못 허용할 수 있어 전체 CPU 2% 등의 값으로 자동 완화하지 않습니다.
- 완료 문구와 실행·일시정지·라이선스 대기 문구가 함께 보이면 실행 중 신호를 우선합니다.
- 창 제목에 버전을 표시합니다. 기본 1분, 설정에서 1~60분으로 조절하는 확인 간격은 유지합니다.

## 설치와 업데이트

1. 기존 스케줄러 트레이 메뉴에서 **종료**를 선택합니다. PowerSI는 그대로 둡니다.
2. `SPD-Scheduler-Setup-0.1.2.exe`를 실행하여 업데이트합니다.
3. 다시 실행한 후 **시작**을 누릅니다. 기존 큐·예약·설정은 보존되며 유휴 관측은 다시 시작합니다.

업데이트 후에도 대기한다면 **감시 상세**의 초과 조건과 PID를 확인하세요. PID와 실행 파일명에 내부 정보가 포함될 수 있으므로 공개 이슈에 내용을 올리기 전에 확인하세요.

## 검증 범위

실제 PowerSI를 실행하지 않는 합성 프로세스·로그 회귀 테스트로 검증합니다. PID 재사용, 여러 유휴 창, 64 논리 프로세서의 CPU 표시, 실제 solver 활동 차단, 혼합 상태 문구를 포함합니다.

현장에서 관측된 높은 CPU의 실제 원인이 PID 재사용이었는지는 아직 확인되지 않았습니다. 이 릴리스는 확인된 감시 오류를 수정하고 원인 확인에 필요한 정보를 제공합니다. 실제 PowerSI GUI 연동의 전체 실측 검증은 남아 있으며, 저부하 추정은 완료의 증명이 아닙니다.
