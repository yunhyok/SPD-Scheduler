SPD Scheduler v0.1.3

## 변경 사항

- 유휴 판정을 통과한 직후의 짧은 재검사 간격 때문에 관측 시간이 초기화되고 실행이 지연될 수 있던 오류를 수정했습니다. 시작 직전의 새 프로세스, 실행 중 신호, 관측 실패와 의미 있는 리소스 활동은 계속 검사합니다.
- PowerSI 상태 표시줄의 여러 항목과 UI Automation의 Text/Value를 읽도록 보강했습니다. 현재 실행 중 신호를 우선하며 과거 Output의 완료 문구를 현재 상태로 사용하지 않습니다.
- 같은 PowerSI의 실행 중 → 완료 전이를 새로 관측하고 모든 창 및 자식의 저부하가 한 확인 간격 유지되면 긴 사용자 지정 유휴 시간을 단축할 수 있습니다. 처음부터 완료로 보이던 창과 상태를 읽을 수 없는 창에는 적용하지 않습니다.
- 기본 저부하 기준을 CPU 합계 50%(1코어 기준) 미만, 메모리 변화 128 MiB 이하, 연속 60초로 조정했습니다. I/O 64 KiB/s와 확인 간격 1분은 유지합니다. 한 코어를 약 100% 사용하는 BbsCon 등 실제 자식 활동은 계속 대기 사유입니다.
- 이전 기본 CPU 1%·메모리 16 MiB 조합만 한 번 변경합니다. 이 조합에서 유휴 시간도 이전 기본 180초이면 60초로 변경합니다. 사용자 지정 값과 예약·대기열은 유지합니다.
- **시작** 시 즉시 첫 확인을 수행합니다. **지금 확인**과 마지막·다음 확인 시각을 표시합니다. 지금 확인은 유휴 조건을 무시하는 강제 실행이 아닙니다.

## 업데이트

1. 기존 SPD Scheduler 트레이 메뉴에서 **종료**를 선택합니다. PowerSI는 그대로 둡니다.
2. `SPD-Scheduler-Setup-0.1.3.exe`를 실행합니다.
3. 스케줄러를 열고 **시작**을 누릅니다. 화면의 마지막·다음 확인 시각과 유휴 관측 상태를 확인합니다.

기본 설정에서 첫 기준점 이후 온전한 60초 저부하 구간이 필요합니다. 완료 직후의 측정 평균에 직전 계산이 포함되거나 프로세스 구성이 바뀌면 한 번 더 확인해야 할 수 있습니다. 1분 확인 간격은 완료 후 1분 이내 실행 보장을 의미하지 않습니다.

## 검증 범위

실제 PowerSI를 실행하지 않는 합성 스냅샷·로그 테스트로 짧은 재검사, 상태 전이, 여러 GUI와 활동 중인 자식, 설정 이전 및 큐 보존을 확인합니다. 자체 작업의 완료·저장·종료 검증은 유지합니다.

실제 워크스테이션의 PowerSI 상태 표시줄 접근성과 전체 GUI 연동은 아직 실측 검증하지 않았습니다. 저부하는 완료의 증명이 아니며, 상태를 읽지 못하는 저부하 작업은 유휴로 오인할 수 있습니다. 설치·업데이트 관리를 위해 정식 Release로 제공합니다.
