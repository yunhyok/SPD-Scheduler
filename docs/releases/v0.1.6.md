SPD Scheduler v0.1.6

## 수정 사항

- 자체 실행한 PowerSI의 프로세스 신원을 읽지 못하면 완료 검사 전에 `확인 필요`로 멈추던 경로를 수정했습니다. 종료된 자식 PID가 다른 프로세스에 재사용된 경우, 생성 시각만으로 이전 자식과 다름을 확인한 뒤 경로 조회를 생략합니다.
- 프로세스 신원은 한 Windows 핸들에서 확인하며, 실행 파일 경로는 모듈 목록 조회 대신 `QueryFullProcessImageName`으로 읽습니다. 조회 도중 종료된 경우에는 같은 핸들에서 종료를 재확인합니다. 실제 접근 거부를 종료로 간주하지 않습니다.
- 일시적인 신원 조회 실패는 **프로세스 확인 재시도 대기**로 처리합니다. 다음 확인에서 재시도하며, 이 실패만으로 자동 진행을 끄지 않습니다. 실패한 PID·실행 파일명·조회 단계·Windows 오류를 작업 상세와 로그에 표시합니다.
- 저장 직전의 신원 재확인만 일시적으로 실패한 경우에도 저장 명령을 보내지 않고 다음 점검에서 완료를 재관측합니다. 자동 진행은 유지하며, 확인된 신원 불일치는 계속 보류합니다.
- 자식 프로세스 조회가 막혀도 신원이 확인된 PowerSI의 현재 실행 시작 기록은 보존합니다. 이후 조회가 회복되면 완료 확인을 이어갑니다. 조회가 불명확한 동안에는 저장·종료와 후속 실행을 보류합니다.
- 이전에 보류된 작업도 현재 실행의 완료 근거와 프로세스 정리가 확인되면 복구할 수 있습니다. 완료 문구만 있거나 실행 ID가 다른 로그는 자동 완료로 승인하지 않습니다.

## 업데이트와 기존 실행 복구

1. **PowerSI 창은 유지**하고 스케줄러만 트레이 메뉴의 **종료**로 닫습니다.
2. `SPD-Scheduler-Setup-0.1.6.exe`를 설치하고 스케줄러를 엽니다.
3. **지금 확인**으로 기존 실행을 확인합니다. 현재 실행의 시작·완료 기록이 있으면 저장·종료를 이어갑니다. 완료한 SPD를 **다시 대기**로 돌릴 필요는 없습니다.
4. 기존 항목이 **완료**로 바뀌면 **시작**을 눌러 후속 큐를 활성화합니다. 앱 재시작 후 신규 실행은 항상 일시정지로 시작합니다.

이전 버전이 시작 기록을 남기기 전에 조회 실패로 멈췄다면 업데이트만으로 완료를 승인할 수 없습니다. 보류가 남으면 **작업 상세**의 PID·오류와 해당 실행 폴더의 `events.log`, `freshness.json`을 확인해야 합니다. 파일명·경로·설계 정보가 포함된 원본은 공개 이슈에 게시하지 마세요.

## 검증 범위

회귀 테스트 146개 통과. PID 재사용, 종료와 조회의 경합, 접근 거부, 자식 조회 실패 중 시작 기록 보존, 재시작 후 완료 복구, 저장 직전 조회 실패와 복구, 저장 후 자식 종료 대기, 후속 큐 진행을 합성 스냅샷·로그와 테스트 프로세스로 검사했습니다. 기존 완료 문구만으로 저장하지 않는 조건도 검사했습니다.

이 PC에서는 실제 PowerSI, 사용자 BAT/Tcl, 실제 SPD 시뮬레이션을 실행하지 않았습니다. 보고된 워크스테이션에서 어느 PID의 조회가 실패했는지는 아직 확인되지 않았으며, 실제 PowerSI의 완료·저장·종료 연동은 별도 허용 PC에서 확인해야 합니다.
